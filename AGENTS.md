# Lynth module and API requirements

- Users describe goals and solve them with `by lynth`; they should not need procedure names.
- `import Lynth` is the sole consumer entry point. Export the `lynth` tactic, its options, the provided real/complex functions (including `Real.digamma` and `Real.zeta`), and the declarations needed to type-check or reduce generated proofs.
- Every Lynth implementation source uses Lean's `module` system. Keep procedures and proof-only supporting lemmas private unless required by generated proofs or directly exercised by the existing unit tests. Export those test helpers, their required types, and generated-proof references through `Lynth`. Keep theorem proof bodies hidden. Implementation modules may use `import all` for private package access without enabling downstream `allowImportAll`.
- Public compiler registrations should be limited to the metadata needed by the exported tactic and proof interface.
- All tests use ordinary `import Lynth` (or `public import Lynth`), never `import all Lynth` or implementation submodules. Additional Lean/Mathlib imports are allowed. Export only the internal helpers and dependencies actually needed by these tests.
- Keep the original headers without `module` in these six internal tests to preserve their original heartbeat limits: `Test/Euf.lean`, `Test/Quant.lean`, `Test/FinSearch/Patterns.lean`, `Test/Sat/CompileTest.lean`, `Test/IntervalArith/IntegralKernelCertificates.lean`, and `Test/IntervalArith/NestedCertificates.lean`. Consumer checks such as `Test/ModuleInterface.lean` retain `module`.
- Grind, its ported implementation, and its tests are exceptions: leave them unchanged except for optional cosmetic changes; their separate module imports remain allowed.
- Keep module migrations structural: change imports, visibility, phases, compiler annotations, and file organization only. Preserve algorithms, declaration types, definition bodies, and theorem statements. Small proof-body fixes required by the module migration are allowed only when proof performance is preserved.
- Prove reusable Array compatibility facts while building the library. Generated proofs should apply those lemmas instead of rebuilding their proofs. Export only the bridge lemmas directly needed by generated proofs; keep their proof bodies and supporting lemmas private. Keep computational checker definitions and native evaluation unchanged.
- Preserve the original test heartbeat limits and measured-budget comments. Do not raise limits or bypass their checks. Ask before introducing workarounds or performance trade-offs.
- Limit changes to this module refactor, its introduced repeated proof generation, and the approved test-helper exports needed to remove `import all Lynth` from tests. Leave earlier proof-generation code unchanged.
